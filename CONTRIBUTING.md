# Contributing

Issues and pull requests are welcome for the draft format, reference implementation, examples, and evaluation protocol. Please open an issue before a breaking format change.

A format proposal should state the problem, a concrete example, affected fields, migration impact, privacy implications, and how it relates to W3C PROV, RO-Crate, C2PA, or other relevant prior work. Add a negative test when a new rule rejects input.

Do not submit private transcripts, hidden reasoning, credentials, patient data, personal paths, or material you cannot license for public redistribution. Use synthetic or explicitly licensed fixtures. Run the unit tests and validate both example records before opening a pull request.

The maintainer reviews and decides whether a change enters a dated draft. Discussion does not imply adoption by any standards body or by ARIA.
